# The rules

Read in this order before changing code in a project that follows them:

1. [Code](code.md): one class per job, loose functions, names, errors, the environment.
2. [Files and folders](files-and-folders.md): `<thing>.<role>.ts`, subdomains then kinds, packages.
3. [Modules](modules.md): bounded contexts, contracts and events, the layout of an application module, HTTP.
4. [Tests](tests.md): beside the code, through the public face, stand-ins and shared cases.
5. [Changing existing code](changing-code.md): how a project that doesn't follow the rules yet gets there.

Then copy from [samples](samples.md) and check your change against the [do's and don'ts](dos-and-donts.md).

A project's own guide comes after these. It may add rules and roles of its own, and says where it differs on purpose; where it is silent, these rules apply.
